Démarrer

Prise en main

Node:Cue permet de déclencher les sons d’un show depuis trois espaces de travail : Cuelist, Pads et Playlist.

Les espaces de travail

Node:Cue s’organise autour de trois espaces de travail : Cuelist, Pads et Playlist. Chacun propose une organisation des contenus, des commandes et des réglages adaptés à son usage.

Espace de travailUsage
CuelistConduite ordonnée de Cues audio, MIDI ou OSC.
PadsDéclenchement rapide de sons à la demande.
PlaylistEnchaînement fluide de morceaux, sans interruption.

Lire un fichier

Pour commencer, créez un projet avec File → New Session, puis enregistrez-le avec File → Save As. Le fichier .ncue conserve votre préparation.

Ouvrez Preferences avec Ctrl + P. Dans Local Preferences → Audio, choisissez la sortie du bus Cuelist, puis cliquez sur Apply and Close.

Dans la vue Cuelist, déposez un fichier audio depuis l’Explorateur Windows. Sélectionnez la Cue créée, puis cliquez sur Go pour la lire.

Avant le show

Le mode Show protège la préparation contre les modifications accidentelles tout en conservant les commandes de lecture. Activez-le dans la barre de statut lorsque votre projet est prêt.

Avant le show, vérifiez les fichiers dans File → Project Health et testez les sorties audio ainsi que les commandes utilisées.

Démarrer

Interface

L’interface de Node:Cue associe une vue principale, un Menu latéral et un Volet inférieur. Ces zones permettent de préparer les éléments, de contrôler leur lecture et de suivre le show.

Zones principales

Les boutons Cuelist, Pads et Playlist, dans la barre de titre, permettent de choisir le lecteur affiché dans la vue principale. Le bouton Flow ouvre les réglages de transition entre ces lecteurs.

  • Barre de contrôle : regroupe les commandes de lecture et indique l’élément qui sera lancé par Go.
  • Contenu du lecteur : présente les Cues, les Pads ou les tracks du lecteur actif.
  • Menu latéral : rassemble le panneau de suivi des lectures, les vues compactes des lecteurs, les bus et Project Browser. Tab permet de l’afficher ou de le masquer.
  • Volet inférieur : affiche les propriétés de l’élément sélectionné, sa waveform, ses traitements et ses réglages Timecode. Ctrl + Tab permet de l’afficher ou de le masquer.
  • Barre de statut : donne accès aux préférences, au thème, aux modes Edit et Show, aux raccourcis globaux des Pads, à MIDI Map, à Sync, aux Logs et aux fenêtres détachées.

Lorsque le Menu latéral est suffisamment large, son mode split permet d’afficher deux vues côte à côte. Chaque colonne peut être redimensionnée. Le panneau de suivi des lectures et Project Browser peuvent occuper les deux colonnes ou une seule.

Les commandes d’un lecteur compact agissent sur ce lecteur, même si une autre vue occupe la fenêtre principale.

Edit et Show

Le mode Edit permet d’importer des fichiers, d’organiser le projet et de modifier les propriétés des éléments.

Le mode Show verrouille ces opérations d’édition. Les commandes de lecture, les réglages de transport, la navigation dans la waveform et les bypass restent disponibles. Le passage d’un mode à l’autre ne modifie pas les lectures en cours.

Démarrer

Projets et médias

Un projet rassemble les Cuelists, les Pad Sets, les Playlists et leurs réglages dans un fichier .ncue. Les fichiers audio et les images utilisés par ces éléments doivent également être disponibles sur l’ordinateur.

Enregistrer et déplacer un projet

Lors du premier enregistrement, Node:Cue crée un dossier portant le nom du projet. Par défaut, il se trouve dans le dossier NodeCue de vos Documents Windows. File → Save enregistre les modifications du projet. Save As permet de l’enregistrer sous un autre nom ou dans un autre dossier.

Dans File → Project Health, Missing indique un fichier introuvable et External un média situé hors du dossier du projet. La commande Collect Project Media rassemble les médias dans ce dossier afin de faciliter leur déplacement.

Pour utiliser le projet sur un autre ordinateur, copiez le dossier complet, puis ouvrez le fichier .ncue avec File → Open Project. Save As ne copie pas les médias : après un changement de dossier, utilisez Collect Project Media pour les rassembler dans le nouvel emplacement.

Node:Cue accepte les fichiers WAV, MP3, FLAC, OGG/OGA, AAC, M4A/MP4 et AIFF/AIF/AIFC.

Gérer plusieurs listes

Node:Cue permet de gérer plusieurs Cuelists, Pad Sets et Playlists dans un même projet. Project Browser permet de créer ces listes supplémentaires et de passer de l’une à l’autre.

Vous pouvez également dupliquer, renommer ou réordonner les listes depuis Project Browser. Ces opérations sont aussi accessibles dans File → Project Properties → Lists.

Vous pouvez ajouter un commentaire à chaque liste dans la colonne Notes de Project Properties → Lists. Ce commentaire apparaît ensuite dans Project Browser. Les préfixes CL (Cuelist), PS (Pad Set) et PL (Playlist) distinguent les trois types de listes ; leur numéro peut être compris entre 1 et 99.

Projet ou préférence locale ?

Project Properties regroupe les réglages du projet ouvert : son nom, ses listes, ses points de patch MIDI/OSC et ses options de lecture.

Local Preferences regroupe les réglages propres à l’ordinateur : sorties audio, périphériques MIDI, endpoints OSC, entrée Timecode, connexion Sync, raccourcis généraux et préférences d’affichage. Les affectations locales des points de patch doivent aussi être adaptées sur chaque ordinateur.

Restaurer un état précédent

Les backups conservent des états précédents du projet et offrent une sécurité supplémentaire lorsque Ctrl + Z ne permet plus de revenir en arrière. File → Backups permet de choisir une sauvegarde à restaurer. La restauration remplace l’état actuel du projet : enregistrez d’abord les modifications que vous souhaitez conserver. Si le dossier du projet n’est plus disponible, utilisez Save As pour enregistrer la récupération ailleurs.

L’option Open last project on startup, dans Local Preferences → Config → General, permet de retrouver la session à l’ouverture de Node:Cue, y compris ses modifications non enregistrées, grâce aux sauvegardes automatiques.

Démarrer

Commandes de lecture

Chaque lecteur dispose de commandes de transport pour contrôler ses lectures.

Commandes de base

Go Entrée lance l’élément indiqué dans la Barre de contrôle. Pour un élément audio, la lecture part de la position réglée manuellement dans la waveform ou du marqueur Start si la tête de lecture n’a pas été déplacée manuellement.

Pause / Resume Espace suspend les lectures concernées, puis les reprend à la même position. Les attentes (Pre-wait et Post-wait) sont également suspendues.

Stop Échap arrête les lectures. Fade Out Retour arrière diminue progressivement leur niveau jusqu’à l’arrêt. Ces commandes annulent aussi les attentes et les départs différés associés.

Stop all Échap × 2 arrête tous les lecteurs et les préécoutes.

Régler la portée des commandes

Dans Project Properties → Project → Transport button scope, les options de portée permettent de choisir si Pause Espace, Stop Échap et Fade Out Retour arrière agissent sur leur lecteur ou sur tous les lecteurs.

Lorsque Fade Out agit sur tous les lecteurs, sa durée est commune aux lecteurs. Sinon, chaque lecteur conserve sa propre durée.

Attention

Les changements effectués dans Local Preferences ne s’appliquent qu’aux projets créés ensuite. Pour modifier le projet actuellement ouvert, utilisez Project Properties.

Naviguer

Dans la Cuelist, Previous ↑ et Next ↓ permettent de sélectionner une autre Cue sans la lancer.

Dans Playlist, les boutons Previous et Next sélectionnent une autre track lorsque la lecture est arrêtée. Pendant la lecture, ils enchaînent vers la track précédente ou suivante. Si la Playlist est en pause, ils arrêtent la track suspendue et sélectionnent la track adjacente sans lancer le son.

Lecteurs

Cuelist

La Cuelist permet d’organiser les Cues dans l’ordre d’un show. Une Cue peut lire un son, envoyer une commande MIDI ou OSC, arrêter une lecture ou rassembler d’autres Cues dans un groupe.

Préparer et lancer une Cue

En mode Edit, déposez un fichier audio dans la Cuelist ou utilisez Add audio cue. La sélection d’une Cue affiche ses propriétés dans le Volet inférieur.

Le nom et l’ID permettent de repérer la Cue dans la conduite. La waveform permet de visualiser le son et d’ajuster les marqueurs Start, End, Fade In et Fade Out. Le bouton Go lance la Cue indiquée dans la Barre de contrôle.

Dans Local Preferences → Config → Cuelist, Advance selected cue on Go permet de sélectionner automatiquement la Cue suivante après un lancement. Keep editor on launched cue maintient le Volet inférieur sur la Cue lancée pour en suivre la lecture, puis affiche automatiquement la Cue suivante à la fin de la lecture.

Une Cue placée sur Off reste dans le projet avec ses réglages, mais ne peut pas être lancée et est ignorée par les enchaînements.

Programmer l’enchaînement

Pre-wait ajoute une attente avant le premier lancement de la Cue. Post-wait ajoute une attente après son exécution.

Play Count définit le nombre total de passages. Infinite play répète la lecture jusqu’à une interruption. Lorsque Play Next est activé, la Cue suivante est lancée après les répétitions et les attentes prévues.

Overlap permet de démarrer la Cue suivante avant la fin de l’étape courante. La valeur indiquée dans ce champ avance d’autant le lancement de la Cue suivante.

Exemple

Pour lire deux annonces avec deux secondes entre elles, activez Play Next sur la première Cue et réglez son Post-wait sur 2 secondes, sans Overlap.

Control Cues

Add stop cue ajoute une Cue Stop à la Cuelist pour inscrire l’arrêt d’une autre Cue dans la conduite.

Dans ses propriétés, choisissez dans Target la Cue à arrêter. Le réglage Fade out permet de choisir le mode d’arrêt :

  • Target fade reprend le Fade Out paramétré dans les propriétés de la Cue cible.
  • Custom fade permet de définir une durée de fade différente pour cet arrêt.
  • Désactiver Fade out arrête la Cue cible sans fade.

Add MIDI cue et Add OSC cue ajoutent des Cues de commande. Leur destination et leur message se règlent dans les propriétés. Les chapitres MIDI et OSC expliquent la configuration des sorties.

Ces Control Cues peuvent également déclencher les transitions de Playback Flow lorsque l’option correspondante est activée.

Les Group Cues permettent de rassembler plusieurs Cues dans une même étape.

Lecteurs

Group Cues

Une Group Cue rassemble plusieurs Cues internes. Son mode de lecture permet de les lancer ensemble, de les piloter comme une sous-liste ou de les enchaîner automatiquement.

Créer un groupe

Dans la Cuelist, Create empty group crée un groupe vide. Pour y ajouter des Cues, sélectionnez-les, faites un clic droit sur la sélection, puis choisissez Move to group dans le menu qui apparaît.

La commande Group selected cues Ctrl + G permet de regrouper directement au moins deux Cues adjacentes.

Ungroup supprime le groupe en conservant ses Cues internes.

Sélectionnez la Group Cue pour choisir son Mode dans les propriétés. Son bouton On/Off permet de rendre l’ensemble du groupe disponible ou indisponible sans modifier l’état individuel des Cues internes.

Mode de lecture

En mode Group Play, un Go sur la Group Cue lance toutes les Cues internes simultanément. Chaque Cue interne conserve ses attentes et ses répétitions, mais ses paramètres Play Next et Overlap ne sont pas utilisés.

Le groupe peut être répété : la répétition suivante commence une fois toutes les Cues internes terminées, Post-wait compris. Le Post-wait du groupe s’ajoute s’il est défini.

Le mode Sublist sert essentiellement à organiser la Cuelist en regroupant les Cues d’une même partie du show. Il conserve le fonctionnement habituel des Cues internes, déclenchées par les Go de l’opérateur ou par leurs propres réglages Play Next et Overlap. Un Go sur la Group Cue lance la première Cue interne disponible. Les répétitions, le Post-wait et le Play Next de la Group Cue sont inactifs.

Lorsqu’une Group Cue est en mode Sequence, le Sequence manager apparaît dans le Volet inférieur. Les Cues internes s’enchaînent automatiquement dans leur ordre. Les chevauchements se règlent dans ce gestionnaire ; les Play Next et Overlaps individuels des Cues internes ne sont pas utilisés.

Une Cue interne peut toujours être lancée directement par un Go sur cette Cue. Elle fonctionne alors comme n’importe quelle autre Cue, indépendamment du mode de la Group Cue.

Le Gain de la Group Cue s’ajoute au gain des Cues audio internes, y compris lorsqu’elles sont lancées individuellement. Il ne remplace pas leurs réglages de gain.

Lecteurs

Pads

Les Pads permettent de déclencher des sons à la demande, sans avoir à les organiser chronologiquement dans une liste.

Préparer et lancer un Pad

En mode Edit, déposez un fichier audio sur une cellule vide pour créer un Pad. Déposer un autre fichier sur un Pad existant remplace son média.

Le bouton d’édition du Pad permet d’ouvrir ses Properties sans le lancer. Vous pouvez y modifier son nom, ses réglages audio, sa couleur, sa couleur de texte et son image.

La waveform permet de visualiser le son et d’ajuster les marqueurs Start, End, Fade In et Fade Out.

Cliquez sur le Pad pour le lancer, ou double-cliquez si le mode Double click est actif.

Couleurs et images

Les palettes de Text color et Pad color appliquent immédiatement la couleur choisie. Cancel annule les changements réalisés depuis l’ouverture de la palette pour les Pads concernés. Save as Default conserve une couleur pour les nouveaux Pads ; choisir Auto puis l’enregistrer comme défaut rétablit les couleurs automatiques.

Dans les presets, Auto utilise la couleur automatique du fond ou du texte. La couleur automatique du texte s’adapte au fond du Pad pour choisir le meilleur contraste.

Le bouton Default rappelle la couleur enregistrée par défaut et permet de la réappliquer au Pad. Les boutons Image, Expand image / Adapt image et Clear image permettent de gérer son image de fond.

Clic et Re-click

Pad launch interaction, dans Local Preferences → Config → Pads, permet de choisir un déclenchement par Single click ou Double click. Le bouton correspondant dans la vue principale et dans le Menu latéral permet aussi de changer ce mode.

Lorsqu’un Pad est déjà actif, un nouveau déclenchement applique son action de Re-click : Stop, Restart ou Pause / Resume. Le clic direct et les raccourcis propres au Pad utilisent ce comportement.

Default re-click action, dans Local Preferences → Config → Pads, définit l’action des nouveaux Pads. Les Pads existants conservent leur réglage.

Le bouton Go Entrée lance ou relance le Pad sélectionné depuis la position réglée manuellement dans la waveform, ou depuis Start si la tête de lecture n’a pas été déplacée manuellement. Il n’applique pas l’action de Re-click.

Pages de la grille

La grille des Pads est réglable de 3 × 3 à 5 × 5, indépendamment pour chaque page.

Réduire le nombre de lignes ou de colonnes ne supprime pas les Pads masqués, mais les rend inaccessibles. La barre d’état signale la présence de Pads masqués.

La molette, Page Up et Page Down permettent de changer de page ; Home revient à la première.

Répétitions et exclusivité

Play Count, dans les propriétés, définit le nombre de passages du Pad. Infinite play répète sa lecture jusqu’à une interruption.

Le mode Multi permet de superposer plusieurs Pads. En mode Single, un nouveau lancement interrompt les autres Pads selon la transition configurée. Passer de Multi à Single ne coupe pas à lui seul les lectures déjà actives.

Le fonctionnement des modes et des transitions est décrit dans Play Mode.

Lecteurs

Playlist

La Playlist permet d’enchaîner des tracks dans l’ordre de la liste.

Préparer et lancer une track

En mode Edit, déposez les fichiers audio dans la Playlist. Glissez les lignes pour modifier leur ordre. La sélection d’une track affiche ses propriétés audio dans le Volet inférieur.

La waveform permet de visualiser le son et d’ajuster les marqueurs Start, End, Fade In et Fade Out.

Sélectionnez la track de départ, puis cliquez sur Go Entrée. La Playlist poursuit la lecture avec les tracks suivantes selon les réglages de transition et de boucle.

L’ID d’une track correspond à sa position dans la liste. Hors du mode Random, déplacer une track réattribue automatiquement les IDs.

Properties d’une track

Trims et transitions

Auto Trim règle automatiquement les paramètres Start et End de chaque track pour supprimer les silences au début et à la fin du fichier.

Régler manuellement Start ou End sur une track rend ce paramètre indépendant de la fonction Auto Trim. Le réglage manuel est ainsi conservé, même si vous désactivez puis réactivez Auto Trim.

Pour que ce paramètre soit de nouveau réglé par Auto Trim, cliquez sur le bouton M ou sur Switch to Auto Trim sur le marqueur correspondant.

Overlap permet d’automatiser les crossfades entre deux tracks. Crossfade duration détermine la durée de leur transition.

Vous pouvez appliquer automatiquement un fade-in à chaque lancement par Go dans la Playlist. Dans Project Properties → Project → Go mode, choisissez Fade In et réglez sa durée.

Boucles et ordre aléatoire

Le bouton Loop propose trois états.

  • Off : la lecture s’arrête à la fin de la dernière track de la liste.
  • Loop playlist : à la fin de la dernière track de la liste, la lecture continue en reprenant au début de la liste.
  • Single track : répète uniquement la track lue.

En haut de la Playlist, Random permet de passer en lecture aléatoire. Shuffle permet de remélanger la Playlist en mode Random. Auto déclenche automatiquement un Shuffle à chaque fin de Playlist en mode Random.

Reprendre après un arrêt

Pause / Resume Espace reprend une track à l’endroit où sa lecture a été suspendue.

Après un Stop Échap, l’indication Stopped at et le bouton Resume permettent de repartir à la position conservée dans la session. Un nouveau lancement remplace ce point de reprise.

Last played track indique la dernière track terminée naturellement.

Lecteurs

Entrée AUX

L’entrée AUX permet de diffuser une source audio externe à Node:Cue. Elle permet notamment de récupérer le son d’une playlist lue dans une autre application ou dans un navigateur, pour centraliser le contrôle audio dans Node:Cue et bénéficier des transitions gérées par la fonction Flow.

Configurer l’entrée

Le menu de l’auxiliaire, dans la Barre de contrôle de la vue Playlist, permet de choisir le périphérique d’entrée de l’auxiliaire.

Pour récupérer le son d’une autre application, affectez-lui, dans les paramètres Windows, une sortie vers un câble audio virtuel. Nous recommandons VB-CABLE de VB-Audio. Dans Node:Cue, sélectionnez comme source de l’entrée AUX le périphérique virtuel correspondant à cette sortie.

Pour lancer la lecture de l’auxiliaire, sélectionnez la ligne AUX dans la zone de contenu de la Playlist, puis utilisez Go pour ouvrir sa diffusion vers le bus Playlist.

La transition AUX / Playlist transition règle le passage entre l’entrée et les tracks.

Passer de la musique à AUX

Un lancement d’AUX interrompt les tracks des Playlists et leurs départs automatiques. Le lancement ou la reprise d’une track referme AUX selon la transition configurée.

Stop Playlist et Fade Out ferment la diffusion AUX. La source reste sélectionnée et peut être rouverte par un nouveau Go. Lorsque la cible est AUX, Pause, Previous, Next et Loop ne sont pas disponibles.

Les vumètres AUX indiquent le niveau d’entrée même lorsque sa diffusion est fermée.

Dans le panneau des lectures en cours, l’affichage de l’entrée AUX indique si sa diffusion est ouverte, même lorsque la source est silencieuse.

Configurer AUX sur le Backup avec Sync

Dans le cadre de la fonction Sync, le périphérique AUX est choisi séparément sur le Primary et sur le Backup. La fonction Sync ne transporte pas le signal audio de cette entrée.

Pour que l’entrée AUX soit disponible sur le Backup, la source audio doit aussi parvenir à cet ordinateur. Configurez son entrée AUX et vérifiez son routage audio avant d’activer la synchronisation.

Transitions

Play Mode

Play Mode permet de choisir la manière dont sont lus les Cues et les Pads.

Choisir un mode de lecture

En mode Multi, plusieurs Cues ou plusieurs Pads peuvent être lus simultanément.

En mode Single, une seule Cue, hors exceptions liées au fonctionnement des Group Cues, ou un seul Pad peut être lu à la fois. Si une Cue est lancée alors qu’une lecture est déjà en cours dans la Cuelist, la lecture active est arrêtée selon les transitions configurées dans les options du mode Single.

Configurer Cuelist et Pads

La Cuelist et les Pads conservent chacun leurs réglages Play Mode et leurs transitions. Les interruptions entre lecteurs sont configurées dans Playback Flow.

Flow

Playback Flow

Playback Flow est le cœur opérationnel des transitions entre les différents lecteurs de Node:Cue.

Ouvrir Playback Flow

Flow est accessible depuis les trois vues principales de Node:Cue, dans la barre de titre. Cliquez sur le bouton Flow pour ouvrir le menu de paramétrage des transitions entre les lecteurs.

Playback Flow permet d’affecter à chaque scénario deux transitions distinctes : la transition principale et l’Alternative Transition.

Lire le menu

Le menu se lit de gauche à droite. Par défaut, il est paramétré par défaut avec les scénarios suivants :

  • Lorsqu’une Cue est lancée : la Playlist est arrêtée avec un Fade Out de 3 secondes. Avec l’Alternative Transition, la Playlist est également arrêtée avec un Fade Out de 3 secondes avant le lancement effectif de la Cue.
  • Lorsqu’un Pad est lancé : la Playlist est arrêtée avec un Fade Out de 3 secondes. Avec l’Alternative Transition, la Playlist est également arrêtée avec un Fade Out de 3 secondes avant le lancement effectif du Pad.
  • Lorsqu’une track de la Playlist est lancée : la Cuelist et les Pads sont arrêtés avec un Crossfade de 3 secondes. Avec l’Alternative Transition, la Cuelist et les Pads sont arrêtés avec un Fade Out de 3 secondes avant le lancement effectif de la track.

Mettre la Playlist en pause

Activer l’option Pause Playlist when interrupted permet de mettre en pause la lecture de la track en cours plutôt que de l’arrêter.

Appliquer Playback Flow aux Control Cues

L’option Apply Flow to Stop, MIDI, and OSC cues permet de choisir si les Control Cues déclenchent ou non les transitions paramétrées.

Si l’option est désactivée, le lancement d’une Control Cue n’arrête aucune lecture sur les Pads ou la Playlist.

Sauvegarder la configuration par défaut

Cliquer sur Use as new-project default permet de sauvegarder la configuration de Flow afin qu’elle devienne la configuration par défaut des nouveaux projets.

Cela apporte de la flexibilité, par exemple en permettant d’utiliser une transition plus réactive pour un démarrage ponctuel sans modifier le comportement principal du show.

Audio

Audio, waveform et sorties

Les propriétés audio permettent de régler chaque élément avant son envoi vers un bus. Le routage des bus détermine ensuite les sorties physiques utilisées sur l’ordinateur.

Affecter les sorties

Dans Local Preferences → Audio, le choix du Driver détermine les périphériques et les canaux disponibles. En WASAPI, chaque bus peut utiliser son propre périphérique ; en ASIO, les bus utilisent les canaux du pilote choisi.

Bus routing permet d’affecter les bus Cuelist, Pads et Playlist à des sorties Mono ou Stereo. Plusieurs bus peuvent partager une sortie. Leurs faders et leurs boutons Mute restent indépendants.

Lorsqu’un périphérique configuré est perdu, une alerte identifie les bus concernés. L’indication Audio unavailable dans la barre de statut ou sur un bus ouvre les préférences audio. Si le même périphérique redevient disponible, Node:Cue tente de rétablir sa sortie sans changer l’affectation choisie.

Régler un élément audio

La sélection d’une Cue audio, d’un Pad ou d’une track affiche ses réglages dans le Volet inférieur.

  • Gain ajuste le niveau de l’élément. Normalize applique la correction issue de l’analyse de normalisation du fichier.
  • Start et End définissent la partie du fichier qui sera lue.
  • Fade In et Fade Out règlent l’entrée et la sortie progressives de l’élément.
  • BAL règle la balance.
  • Equalizer et Compressor permettent de modifier le spectre et la dynamique avant le mixage dans le bus.

Pour les Cues audio et les Pads, Play Count indique le nombre total de passages, de 1 à 999. Infinite play maintient la répétition jusqu’à une interruption.

Choisir les fades des répétitions

Repeat fades détermine sur quels passages appliquer les fades lorsqu’un élément audio est répété. La première valeur concerne le Fade In et la seconde le Fade Out.

  • First / Last : Fade In au premier passage et Fade Out au dernier.
  • Every / Every : les deux fades à chaque passage.
  • Every / Last : Fade In à chaque passage et Fade Out au dernier.
  • First / Every : Fade In au premier passage et Fade Out à chaque passage.

Une lecture en répétition infinie n’a pas de dernier passage naturel. Ces réglages ne remplacent pas les fades d’arrêt du transport ni les transitions entre lecteurs.

Utiliser la waveform

La waveform permet de visualiser le fichier et de déplacer les marqueurs Start, End, Fade In et Fade Out. Cliquez dans la waveform pour positionner la tête de lecture. Pendant une lecture, ce geste déplace également la position jouée.

Lorsque le gain est trop élevé, des raies rouges apparaissent dans la waveform aux endroits où les crêtes atteignent ou dépassent 0 dBFS avec le gain appliqué. Elles signalent un risque d’écrêtage : réduisez le gain de l’élément concerné.

Limiteur de sécurité

Un limiteur de sécurité agit en sortie, après le mixage des bus. Il réduit automatiquement les crêtes pour éviter l’écrêtage en sortie et la distorsion associée, notamment lorsqu’un gain trop élevé ou plusieurs lectures simultanées font dépasser le niveau maximal.

La molette règle le zoom. Shift + molette déplace la zone visible. La miniature située en dessous permet de déplacer ou de redimensionner cette zone. Compact / L/R choisit une représentation combinée ou des voies séparées.

Le bouton Follow playhead, à gauche de Compact/L/R, active le suivi automatique de la tête de lecture lorsque la waveform est zoomée. Le désactiver permet de garder la zone affichée pour travailler sur un passage sans arrêter la lecture.

Lorsque l’élément n’est pas en lecture, les marqueurs proches de la tête de lecture s’alignent automatiquement sur sa position. Maintenez Shift pendant le déplacement pour ignorer cet alignement.

Les quatre boutons de bypass permettent d’ignorer séparément les trims et les fades sans effacer leurs valeurs. Une croix rouge signale un bypass actif. Le clic droit sur le marqueur permet de modifier le même état. Le raccourci W ramène la tête de lecture au début effectif de l’élément sans changer son état de lecture ou de pause.

Audio

Monitor et préécoute

Monitor permet de préécouter des éléments en parallèle des lectures diffusées sur les bus du show (Cuelist, Pads et Playlist), ou d’écouter les lectures en cours sur ces bus.

Choisir la sortie

Dans Local Preferences → Audio → Monitor, l’option Enable Monitor active le circuit d’écoute. Affectez-lui le périphérique et les canaux utilisés par votre système d’écoute.

Monitor peut utiliser une sortie dédiée ou partager une sortie avec un bus du show. Avec une sortie partagée, la fonction Bus Monitoring est indisponible. La préécoute reste utilisable lorsque les lectures du show sont arrêtées.

Cette configuration peut servir à préparer ou répéter une conduite : l’option Skip waits permet d’ignorer les attentes Pre-wait et Post-wait.

Pendant un show

Pendant un show, désactivez Monitor ou affectez-lui une sortie dédiée, distincte des sorties utilisées pour la diffusion du show.

Préécouter un élément

Le mode Single item permet de préécouter l’élément sélectionné une seule fois, en ignorant les automatisations telles que les répétitions et l’enchaînement automatique de l’option Play Next.

Le mode Show simulation reproduit les transitions, les groupes et les enchaînements d’une conduite. Pour préécouter une Group Cue, activez le mode Show simulation.

Le réglage Timing propose deux options : Skip waits ignore les attentes Pre-wait et Post-wait ; Follow timing les respecte.

Sélectionnez l’élément puis maintenez Ctrl en cliquant sur le grand bouton Go, qui devient PFL Go. Sur un Pad, Ctrl fait apparaître les zones Select et Preview. Pour arrêter les préécoutes, maintenez Ctrl et utilisez Stop All PFL.

L’option Send MIDI / OSC, disponible dans le mode Show simulation, autorise l’envoi de véritables messages MIDI ou OSC vers les destinations configurées. Laissez-la désactivée pour préécouter sans envoyer de messages MIDI ou OSC.

Écouter le show

La fonction Bus Monitoring permet d’écouter un bus Cuelist, Pads ou Playlist, ou leur ensemble avec All buses.

Le mode AFL tient compte du fader et du Mute du bus. Le mode PFL permet une écoute avant ces commandes. Le réglage Bus Level et le fader Monitor règlent le niveau d’écoute.

Monitor et les préécoutes ne sont pas disponibles sur un Backup qui suit le Primary.

Contrôle

MIDI

Node:Cue peut être piloté en MIDI et peut également envoyer des messages MIDI depuis la Cuelist.

Configurer les périphériques locaux

Dans Local Preferences → Control → MIDI, la partie MIDI input permet de choisir les périphériques dont Node:Cue reçoit les messages. La partie MIDI output permet de choisir les sorties utilisées pour envoyer des messages.

Le bouton + ajoute une entrée ou une sortie. Le bouton Refresh devices actualise la liste des périphériques disponibles après un branchement.

Ces choix restent propres à l’ordinateur. Les affectations qui déterminent ce que déclenchent les messages reçus sont, elles, enregistrées dans le projet avec la fonction MIDI Map.

Configurer le patch MIDI du projet

Les Cues MIDI utilisent les destinations définies dans le patch du projet. Chaque destination doit être rattachée à un périphérique de sortie MIDI local.

  1. Ouvrez Project Properties → MIDI Patch et utilisez le bouton + pour ajouter un point de patch.
  2. Dans la colonne Patch point, donnez-lui un nom correspondant à son rôle dans le show.
  3. Dans la colonne Local MIDI Output, choisissez la sortie déclarée dans les préférences locales.

Cette organisation permet la portabilité du projet : d’un ordinateur à l’autre, le patch reste identique. Seuls les périphériques locaux affectés aux points de patch peuvent changer, sans modifier les Cues MIDI.

Renommer un point conserve ses affectations dans les Cues. Pour supprimer un point utilisé, réaffectez d’abord les Cues concernées. Un point Unassigned n’a pas encore de sortie affectée ; une sortie Unavailable doit être vérifiée avant l’envoi.

Affecter les commandes avec MIDI Map

La fonction MIDI Map (accessible dans la barre de statut) associe un message MIDI reçu à une commande de Node:Cue : par exemple un Go, le lancement d’un Pad ou le réglage du niveau d’un bus. Le bouton MIDI Learn apprend le message émis par votre contrôleur.

  1. Choisissez d’abord l’entrée MIDI dans les préférences locales, puis ouvrez MIDI Map depuis la barre de statut.
  2. Dans le panneau d’affectation, cliquez sur + puis choisissez la commande à piloter dans le champ Target.
  3. Cliquez sur MIDI Learn, puis actionnez le bouton, le fader ou le bouton rotatif de votre contrôleur. Le formulaire récupère le type de message, son canal et son numéro.
  4. Cliquez sur Assign pour enregistrer l’affectation dans le projet.
  5. Quittez le mode MIDI Map, puis actionnez de nouveau le contrôleur pour utiliser la commande affectée.

Vous pouvez aussi renseigner manuellement le type, le canal et le numéro du message dans le formulaire. Un double clic sur une affectation existante permet de la modifier ; le bouton Save enregistre alors les changements.

Pendant le MIDI learning, utilisez un fader ou un bouton rotatif émettant un CC absolu, c’est-à-dire une valeur de niveau comprise entre 0 et 127, pour affecter une commande de niveau. Déplacez-le sur une plage suffisante pour que Node:Cue reconnaisse ce contrôle continu.

Envoyer un message avec une Cue MIDI

Une Cue MIDI permet de déclencher l’envoi d’un message MIDI depuis la Cuelist. Elle utilise une destination définie dans le patch MIDI du projet.

  1. En mode Edit, utilisez Add MIDI cue pour ajouter la Cue.
  2. Sélectionnez-la et ouvrez ses Properties dans le Volet inférieur.
  3. Dans le champ Destination, choisissez le point de patch MIDI voulu.
  4. Renseignez le type de message, le canal et ses données, puis lancez la Cue avec Go.

Un message de type Note utilise une note, une vélocité et une durée. Un Control Change utilise un numéro de contrôleur et une valeur. Un Program Change utilise un numéro de programme.

Utiliser MIDI avec Sync

La fonction Sync transmet les points de patch du projet et les affectations MIDI Map. Les entrées MIDI, les sorties MIDI et l’affectation locale de chaque point de patch restent propres à chaque ordinateur.

Préparez les périphériques et les destinations du Backup sur cet ordinateur. Ces réglages locaux restent accessibles pendant qu’il suit le Primary. Tant qu’il le suit, le Backup ignore les commandes MIDI reçues et n’envoie pas les messages des Cues MIDI. Ses destinations locales servent lorsqu’il fonctionne en mode Standalone.

OSC

Node:Cue peut être piloté en OSC et peut également envoyer des messages OSC depuis la Cuelist.

Configurer les connexions OSC locales

Dans Local Preferences → Control → OSC, le bouton + ajoute une connexion nommée, appelée endpoint dans l’application. Chaque connexion a un nom, un mode, une adresse ou une interface et un port UDP.

ModeRôle et réglages
ReceiveReçoit des messages destinés à Node:Cue. Choisissez l’interface réseau locale sur laquelle écouter et le port UDP utilisé.
SendEnvoie des messages depuis Node:Cue. Renseignez l’adresse IP et le port UDP du destinataire.

Pour communiquer dans les deux sens, créez une connexion Receive et une connexion Send. Ces connexions restent locales à l’ordinateur ; elles ne sont pas enregistrées dans le projet.

Pour la réception, l’émetteur doit envoyer ses messages à l’adresse IP de l’ordinateur Node:Cue et au port choisi. Vérifiez aussi que le pare-feu Windows autorise cette communication. Deux connexions Receive ne doivent pas utiliser la même interface et le même port.

Configurer le patch OSC du projet

Les Cues OSC utilisent les destinations définies dans le patch du projet. Chaque destination doit être rattachée à une connexion OSC locale en mode Send.

  1. Créez d’abord un endpoint Send dans les préférences locales.
  2. Ouvrez Project Properties → OSC Patch, puis utilisez le bouton + pour ajouter un point de patch.
  3. Donnez-lui un nom dans la colonne Patch point et choisissez sa connexion dans Local OSC Endpoint.

Cette organisation permet la portabilité du projet : d’un ordinateur à l’autre, le patch reste identique. Seules les connexions locales affectées aux points de patch peuvent changer, sans modifier les Cues OSC.

Renommer un point de patch conserve son utilisation par les Cues. Un point encore utilisé ne peut pas être supprimé : réaffectez d’abord les Cues concernées.

Le patch OSC sert uniquement aux messages OSC sortants émis par les Cues. Les messages entrants qui permettent de contrôler Node:Cue utilisent les endpoints Receive, sans passer par le patch du projet.

Piloter Node:Cue par OSC

Une connexion en mode Receive permet de commander Node:Cue depuis une application ou un appareil capable d’émettre des messages OSC.

L’ensemble des commandes est répertorié dans la référence des commandes OSC.

Adresse OSCAction
/nodecue/cuelist/goLance la Cue indiquée dans la Barre de contrôle.
/nodecue/cuelist/go/12.5Lance la Cue portant l’ID 12.5.
/nodecue/pads/go/7Déclenche le Pad 7.
/nodecue/playlist/goLance la track indiquée dans la Barre de contrôle de Playlist.

Les commandes de la section Active View de la référence OSC agissent uniquement sur la vue active, comme ses commandes de lecture.

La commande générale /nodecue/cuelist/go lance la Cue indiquée dans la Barre de contrôle. Pour choisir une Cue par son ID, utilisez une adresse explicite comme /nodecue/cuelist/go/12.5. Ajouter un argument à l’adresse Go générale ne sélectionne pas une autre Cue.

Chaque lecteur possède sa propre liste ouverte. Les commandes OSC de ce lecteur agissent sur cette liste, même si une autre vue est affichée. Utilisez /nodecue/cuelist/open/CL2, /nodecue/pads/open/PS3 ou /nodecue/playlist/open/PL2 pour changer de liste. Cette opération ne lance aucune lecture et ne coupe pas les lectures de la liste précédente.

Les ID de bus OSC sont 1 pour Cuelist, 2 pour Pads, 3 pour Playlist et 4 pour Monitor. Par exemple, /nodecue/bus/leveldb/4 avec l’argument numérique -6 règle Monitor à -6 dB. /nodecue/aux/leveldb règle AUX de la même manière. La valeur 0 correspond à 0 dB et le texte -inf au silence. Les commandes level conservent leur échelle de 0 à 1. Les commandes Fade Out de Cuelist, Pads, Playlist, AUX et le Fade Out global acceptent une durée de 0 à 60 000 millisecondes (60 secondes). Sans argument de durée, elles utilisent le réglage de fade configuré, limité à 60 secondes.

La commande rewind, par exemple /nodecue/playlist/rewind, ramène l’élément audio sélectionné à son début effectif en conservant son état de lecture ou de pause. /nodecue/stopall et /nodecue/fadeoutall agissent sur toutes les lectures du projet, y compris celles des listes précédemment ouvertes.

Envoyer un message avec une Cue OSC

Une Cue OSC permet de déclencher l’envoi d’un message OSC depuis la Cuelist. Elle utilise une destination définie dans le patch OSC du projet.

  1. En mode Edit, utilisez Add OSC cue pour ajouter la Cue.
  2. Sélectionnez-la et ouvrez ses Properties dans le Volet inférieur.
  3. Dans le champ Destination, choisissez le point de patch OSC voulu.
  4. Renseignez l’adresse OSC et les arguments attendus par ce destinataire, puis lancez la Cue avec Go.

L’adresse OSC commence par /. Elle désigne une commande chez le destinataire, tandis que l’adresse IP et le port de la connexion Send désignent où envoyer le message. L’adresse et les arguments restent propres à la Cue lorsque vous changez la connexion affectée au point de patch.

Utiliser OSC avec Sync

La fonction Sync transmet les points de patch et les Cues OSC du projet. Les connexions OSC et les affectations locales de ces points restent propres à chaque ordinateur.

Préparez les connexions et les destinations du Backup sur cet ordinateur. Ces réglages locaux restent accessibles pendant qu’il suit le Primary. Tant qu’il le suit, le Backup n’exécute pas les commandes OSC reçues et n’envoie pas les messages de ses Cues OSC. Ses connexions locales servent lorsqu’il fonctionne en mode Standalone.

Préparer une touche

Contrôle

Timecode

Le Timecode permet de déclencher des Cues.

Configurer la réception

Dans Local Preferences → Control → Timecode, l’option Enable Timecode permet d’afficher les outils associés. Choisissez MTC avec son entrée MIDI, ou LTC avec son entrée audio et son canal.

Le réglage Frame rate définit la cadence utilisée, en images par seconde. Le réglage Freewheel définit combien de temps Node:Cue peut continuer à faire avancer le timecode en cas de perte du signal.

Le monitor Timecode affiche la valeur reçue et l’état de réception. L’état Locked indique que Node:Cue est synchronisé avec le signal reçu.

L’affichage des outils et l’armement sont distincts. Le bouton Arm autorise les déclenchements des Cues.

Programmer un départ

Dans le Volet inférieur, l’onglet Timecode permet de définir un ou plusieurs timecodes de déclenchement pour une Cue. En mode Edit, sélectionnez la Cue et utilisez Add trigger pour saisir une valeur au format HH:MM:SS:FF : heures, minutes, secondes et images. Capture current timecode permet d’utiliser directement la valeur actuellement reçue.

Après avoir vérifié la Cue, son timecode de déclenchement et la cadence, activez Arm timecode. Lorsque le timecode reçu atteint la valeur programmée, Node:Cue déclenche la Cue en appliquant ses transitions et son Pre-wait. Ces réglages peuvent retarder le début du son.

Disarm empêche les nouveaux déclenchements Timecode sans arrêter les lectures déjà lancées.

Décalage et gestion du signal

Les commandes Shift Cue by et Shift Cuelist by permettent d’avancer ou de retarder les timecodes de déclenchement d’une Cue ou de la Cuelist, selon la portée choisie. Saisissez la durée du décalage, puis utilisez − pour avancer les déclenchements ou + pour les retarder.

Si le signal est perdu après une synchronisation, Freewheel permet à Node:Cue de continuer à faire avancer le timecode pendant la durée configurée. Les Cues programmées pendant cette période peuvent donc encore se déclencher. Si le signal n’est pas revenu à temps, Node:Cue attend de recevoir à nouveau un signal synchronisé avant de déclencher d’autres Cues.

Si le timecode saute plusieurs secondes vers l’avant, les Cues dont le déclenchement a été dépassé ne sont pas lancées automatiquement.

Avec la fonction Sync, seul le Primary déclenche les Cues à partir du Timecode. Le Backup suit les déclenchements du Primary.

Sync

Protocole Sync

Sync permet de sécuriser un show grâce à un système de redondance entre deux ordinateurs exécutant Node:Cue et reliés au même réseau local. Le système sépare le rôle de contrôle (Primary) du rôle de secours (Backup) afin qu’un seul ordinateur reste l’autorité de lecture.

Principe de fonctionnement

Le Primary envoie au Backup les modifications validées du projet et les commandes de lecture. Le Backup applique ces événements dans le même ordre et lit l’audio en parallèle, mais ses commandes locales et ses modifications de projet restent verrouillées tant qu’il suit le Primary.

Si le Primary devient indisponible, le Backup passe automatiquement en mode Standalone et devient alors utilisable par l’opérateur, sans interruption des lectures en cours.

Prérequis

Avant de configurer Sync, vérifiez les points suivants :

  • les deux ordinateurs utilisent la même version de Node:Cue ;
  • les deux ordinateurs sont reliés par un réseau local stable, de préférence en Ethernet ;
  • le projet est sauvegardé sur le Primary ;
  • les médias du projet sont disponibles sur le Backup. Utilisez Collect Project Media pour rassembler les fichiers audio et les images de Pads dans le dossier du projet ;
  • les deux systèmes sont dans un état propre obtenu avec Stop all : aucune lecture, pause, attente, fade ou action différée ne doit être en cours ;
  • les sorties audio, les périphériques et les chemins de secours sont configurés et testés séparément sur chaque ordinateur.

Les rôles

Standalone
L’ordinateur fonctionne seul. C’est l’état normal avant l’association, après Stop Sync et après la perte du Primary.
Primary
L’ordinateur piloté par l’opérateur. Il conserve l’autorité sur les modifications du projet et les commandes de transport.
Backup
L’ordinateur de secours. Il suit le Primary, conserve une lecture audio parallèle et devient disponible pour une reprise manuelle en cas de panne.

La configuration détaillée des rôles et leur association sont décrites dans Configurer Sync.

Sync · Configuration

Configurer Sync

La configuration de Sync se fait dans Preferences → Sync. Les champs affichés dépendent du rôle choisi. Sync n’est jamais activé automatiquement au lancement de Node:Cue : chaque ordinateur démarre en mode Standalone.

Configurer le Primary

Dans le sélecteur de rôle, choisissez Primary. Configurez ensuite :

  • Network interface : l’interface IPv4 locale sur laquelle le Primary accepte la connexion du Backup. Auto conserve le routage normal du système ; une interface explicite limite l’écoute à cette adresse ;
  • Sync port : le port TCP utilisé par la connexion Sync. Il doit être identique sur les deux ordinateurs ;
  • Heartbeat interval : la fréquence des contrôles de liaison, comprise entre 50 et 5000 millisecondes. La valeur par défaut de 100 ms convient à un réseau filaire stable.

Enregistrez les préférences, puis utilisez Sync dans la barre de statut et Start Primary pour attendre la connexion du Backup.

Configurer le Backup

Dans le sélecteur de rôle, choisissez Backup. Configurez ensuite :

  • Network interface : l’interface locale utilisée pour joindre le Primary ;
  • Primary IP : l’adresse IPv4 complète de l’interface réseau du Primary ;
  • Sync port : le même port TCP que celui configuré sur le Primary ;
  • Link resilience : la tolérance aux heartbeats manqués. Fast en tolère 5, Balanced 8 et Safe 15. Safe est le meilleur point de départ lorsque le réseau peut subir de brèves interruptions ; Fast détecte plus rapidement une perte du Primary, mais tolère moins les variations du réseau. Ce paramètre définit essentiellement la vitesse à laquelle le Backup basculera en Standalone en cas de perte de liaison avec le Primary. Un réglage rapide peut provoquer une désynchronisation des deux ordinateurs en cas de gigue trop élevée sur le réseau.

Préparer les contrôles du Backup

Les points de patch MIDI et OSC du projet sont partagés entre les deux ordinateurs. Leurs affectations physiques restent locales et doivent être préparées sur le Backup.

Dans Project Properties → MIDI Patch, affectez chaque point utilisé à une sortie de cet ordinateur dans la colonne Local MIDI Output. Dans OSC Patch, la colonne Local OSC Endpoint permet de choisir l’endpoint OSC local correspondant.

Ces affectations restent modifiables sur un Backup qui suit le Primary, sans modifier les points de patch du projet. Validez-les avec Apply.

Ready indique une destination disponible. Une destination Unassigned n’est pas affectée ; Unavailable signale une destination indisponible. Corrigez ces états et testez les équipements concernés avant de compter sur le Backup pour reprendre le show.

Associer les deux ordinateurs

L’association se fait depuis le bouton Sync de la barre de statut, après avoir enregistré les paramètres de connexion des deux ordinateurs.

  1. Sauvegardez le projet sur le Primary et utilisez Stop all sur les deux ordinateurs pour terminer les lectures et les actions en attente.
  2. Sur l’ordinateur principal, ouvrez Sync et cliquez sur Start Primary.
  3. Sur le Backup, vérifiez l’adresse du Primary puis cliquez sur Connect to Primary.

Si le projet du Primary n’est pas présent sur le Backup, Download project permet de le télécharger avec ses médias. Ce transfert doit être demandé ; l’importation d’un fichier sur le Primary ne le déclenche pas automatiquement.

Si le projet est déjà présent mais que ses réglages diffèrent, utilisez Align from Primary. Si des fichiers manquent après cet alignement, Restore missing files permet de les récupérer.

Les indicateurs Link, Project, Media, Audio, Control et Playback permettent de vérifier les différents aspects de la préparation. Ils ne remplacent pas l’essai des sorties physiques de chaque ordinateur.

Modifier le projet

Une modification d’une Cue, d’un Pad ou d’un élément de Playlist est envoyée au Backup tant que celui-ci possède déjà localement le média concerné. Le fichier audio ou l’image reste propre à chaque ordinateur : une importation sur le Primary ne déclenche pas de téléchargement automatique sur le Backup.

L’ajout d’une nouvelle Cue audio, d’un nouveau Pad ou d’un nouvel élément de Playlist nécessite donc de télécharger le nouveau média sur le Backup avec Download project ou Restore missing files, puis de resynchroniser le projet. Le Backup ne doit pas être considéré comme prêt tant que cette resynchronisation n’est pas terminée.

Le changement de projet, Save As et Collect Project Media doivent être effectués après l’arrêt de Sync. Pour les autres imports de médias, arrêter Sync avant l’opération reste la procédure recommandée afin de préparer le fichier sur le Backup avant de reprendre la synchronisation.

Sync · Opération

Utiliser Sync

Une fois l’association terminée, le Primary devient l’autorité de la session. Le Backup suit les événements lancés sur le Primary et signale les états qui empêchent de considérer le secours comme immédiatement disponible.

Ce qui est synchronisé

Le Primary transmet notamment :

  • les modifications validées des Cues, Pads et éléments de Playlist ;
  • les réglages de lecture, de transitions, de fades, de waits et de boucles ;
  • les commandes Go, Stop, Pause, Resume, Fade Out, Play next et Stop all ;
  • les sélections et les états de lecture nécessaires pour préparer une reprise cohérente.

Ce qui reste propre à chaque ordinateur

Les éléments liés à la machine restent locaux :

  • le périphérique audio et les sorties physiques ;
  • les interfaces, les périphériques et les associations de sorties MIDI locales ;
  • les endpoints OSC locaux et leurs interfaces d’écoute ;
  • les entrées Timecode et leurs paramètres locaux ;
  • les interfaces réseau et les paramètres de connexion Sync ;
  • les chemins locaux des médias lorsque le projet est déjà présent sur les deux ordinateurs.

Le Backup reste en lecture seule pendant qu’il suit le Primary. Les commandes MIDI et OSC sont neutralisées comme effets externes pendant cette phase, tout en conservant leur état de lecture synchronisé. Les mappings MIDI du projet restent identiques, mais leurs destinations physiques sont adaptées aux sorties locales du Backup. Les endpoints OSC Receive restent également configurés localement pour permettre la reprise après un passage en Standalone.

Surveiller l’état de la session

Synced signifie que les événements sont appliqués, que les projets des deux instances correspondent et que les médias requis sont disponibles. Les états Needs Resync, Media missing, Degraded et Diverged indiquent qu’une vérification ou une intervention est nécessaire.

Un état Degraded peut signaler une différence de lecture non bloquante. Un état Diverged indique qu’un événement a été rejeté ou que les projets ne convergent plus. Dans ces deux cas, ne considérez pas le Backup comme prêt sans avoir résolu l’indication affichée.

Après une perte du Primary

Si le Primary tombe, le Backup bascule en mode Standalone et les lectures en cours ne sont pas interrompues. Vous pouvez donc l’utiliser pour continuer le show sans interruption.

Pour rétablir la synchronisation, attendez un moment où aucune lecture n’est en cours, cliquez sur Start Primary sur l’ordinateur principal, puis cliquez sur Connect to Primary sur l’ordinateur de secours.
